# CLAUDE.md — правила агента (всегда в контексте)

Проект: сайт-визитка КП УЗН Деснянського району. Репозиторий: `Butcherok/uzn-desna` (публичный). Владелец: Roman. Бюджет 0 грн.

## Экономия лимитов

- Читать только файлы под задачу. Один и тот же файл не перечитывать.
- План до 5 пунктов → действие или один пакет вопросов.
- Логи и вывод команд — в файл, в ответе только итог.
- Правка — точечная, без переписывания файла целиком.
- Документ базы знаний целиком не читать: найти раздел в `docs/kb-map.md` и взять срез (`sed -n 'A,Bp'`). ТЗ — 319 КБ, один подраздел — единицы килобайт.
- Документ из базы знаний Claude выгружать в файл, а не в переписку. Загрузку туда сверять `md5sum` копии и выгруженного мастера, а не ответом инструмента.
- При старте читаются только два файла. История — `docs/done.md`, найденное попутно — `docs/findings.md`; они открываются по требованию, а не всегда.
- Пределы длины файлов старта держит шаг `docs:check` в `npm run ci`, а не обещание.

## Старт сессии

1. `docs/project-context.md` — состояние и следующий шаг.
2. `docs/roadmap.md` — только если неясно, что в работе.
3. Дальше — только файлы под задачу, по `docs/INDEX.md`. Весь репозиторий не обходить.

## Источник правды

`docs/` на ветке `main`. Задача не закрыта, пока `docs/project-context.md` не обновлён в том же PR, что и код.

## Запреты

- Код, коммиты, PR — только после явного «да» владельца. Обсуждение не является разрешением.
- Секреты, токены, `.env` — не в чат и не в git.
- Не чинить попутно найденное вне задачи: записать и показать владельцу.
- Платные сервисы не подключать.
- Merge в `main` делает только владелец.

## Git

- Одна задача в работе. Одна задача = одна ветка = один PR.
- Ветки: `feat/<тема>`, `fix/<тема>`, `docs/<тема>`, `chore/<тема>`.
- Коммиты: Conventional Commits с областью, на английском. Пример: `feat(news): add facebook sync job`.
- PR: «Что сделано», «Что нарочно не тронуто», «Как проверить».
- Перед PR: `npm run ci` зелёный.

## Проверка

- **Перед подачей ответа прогнать проверки** (правило Заказчика 18.11.2026): то, чем ответ проверяется, прогоняется до его подачи — разбор файла, растр, расчёт, сборка, тесты. Ответ с заведомо непроверенным утверждением или с невыявленной ошибкой не подаётся; непрогнанное называется непроверенным вслух.
- **Перед подачей ответа или решения перебрать варианты исхода** (правило Заказчика 17.11.2026): чем предложенное может не сработать, какие ещё есть пути, что из этого уже проверено, а что нет. В ответ идёт проверенное; непроверенное называется непроверенным вслух, вместе с запасным путём. Это относится и к советам о внешних настройках, которые агент прочитать не может.
- Готово — это зелёная задача CI целиком, а не только `npm run ci`: в `.github/workflows/` бывают шаги вне него.
- Проверяет агент: линтер, типы, тесты, сборка, открытие страницы. **Живой прогон тоже делает агент сам** (правило Заказчика 21.11.2026): встроенный браузер, `gh`, панель Render, админка на Render. Заказчику — только ввод пароля, merge и действия, которые агенту запрещены; шаги с секретами — по runbook.
- **Ждать внешнее — опросом, а не вопросом** (правило Заказчика 21.11.2026): выкладка Render, CI, Lighthouse, Pages, прогон Actions — повторная проверка с паузой (до ~15 мин), затем отчёт. Render с `checksPass` выкладывает только после всех проверок коммита, включая `measure` (~7 мин после слияния).
- «Исправление не помогло» → сначала убедиться, что проверяется новая сборка (номер сборки в подвале сайта, кэш GitHub Pages, проснулся ли Render). Потом одна гипотеза за раз. Две неудачные правки подряд — стоп и разбор.
- Ошибка внешнего API не равна пустому результату: различать «данные», «пусто», «неизвестно».

## Общение

- С владельцем — по-русски. Контент сайта — украинский и английский. Код — английский.
- Уточнения — одним пакетом.
- Шаги для владельца: где → что ввести или нажать → что должно появиться → когда остановиться. Команды PowerShell — отдельными строками, без `&&`.

## Уроки и решения

- Новая ошибка или удачный обход → 1–3 строки в `docs/lessons-learned.md` (сначала проверить, нет ли уже).
- Принятое решение → файл в `docs/decisions/` по шаблону `000-template.md`.
