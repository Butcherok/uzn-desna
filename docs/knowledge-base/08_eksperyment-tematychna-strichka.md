## 1. Главное

1. **Бесплатные новостные API почти все запрещают использование на сайте организации.** NewsAPI.org — только разработка; GNews и Guardian — только некоммерческое, причём GNews считает коммерческим всё, что «используется в ходе деятельности бизнеса». Для сайта предприятия это риск блокировки ключа.
2. **GDELT DOC 2.0 — единственный API без ключа и без ограничения по цели использования**: разрешено любое использование, в том числе коммерческое и государственное, при условии ссылки на GDELT. Отдаёт заголовок, адрес, домен, язык, страну, дату, картинку; отрывка текста нет. Практическая пригодность не подтверждена (раздел 12.3), поэтому в схеме он необязательный источник.
3. **Права на чужие тексты и фото определяет не API, а издатель.** Голый факт новости по закону не охраняется; формулировка, отрывок и фото — охраняются. Поэтому белый список источников важнее выбора API.
4. **Фото из чужих новостей не показываем.** Ни один источник итогового белого списка права на фото не даёт. Карточка — с нашей иллюстрацией по категории.
5. **Итоговая схема:** белый список из трёх работающих источников (КМДА по тегу «Парки та зелені зони», Київзеленбуд головний, The Conversation) + Хмарочос после письменного разрешения редакции; сбор через WP REST, HTML-выборку по тегу и Atom; словарь тем — только там, где у источника нет тематических тегов; синхронизация в GitHub Actions; скрытие карточки редактором. Подробно — разделы 7 и 12.6.
6. **Объём ленты — на нижней границе полезности.** 1,85 внешней карточки в неделю без Хмарочоса, 2,6 с ним (раздел 12.4). Поэтому вытеснение карточек новыми вместо удаления по возрасту — не улучшение, а условие работоспособности блока.

«Коммерческое использование»: сайт без рекламы и платного доступа, но принадлежит предприятию. Для некоммерческих тарифов API это серая зона. Итоговый белый список от неё не зависит: он собран из источников, чьи условия требуют только ссылку, либо из источника с разрешением редакции.

## 6. Фильтрация по теме

Конвейер в GitHub Actions по расписанию (уточнённый порядок — раздел 12.6):
1. Забрать материалы источников белого списка: там, где есть тематические теги — по тегам; где нет — ленту целиком.
2. Записи из источников с тематическими тегами в словарь не прогонять.
3. Остальные: оставить записи, где в заголовке или описании есть слово из словаря тем.
4. Стоп-слова применять только к заголовку; если тематический корень есть в заголовке — стоп-слова не применять вовсе.
5. Убрать дубли по адресу и по нормализованному заголовку.
6. Сохранить в JSON для статики; карточки, скрытые редактором, — не выводить.
7. Ошибка источника ≠ «новостей нет»: оставить прошлые карточки, отметить источник как недоступный (правило брифа, раздел 6).

Что изменено против версии 1.1 (основания — раздел 12.2):
1. Стоп-слова — только по заголовку и только когда тематического корня в заголовке нет.
2. `добрив` убрано из стоп-слов: подкормка насаждений — уход за зеленью, а не сельское хозяйство.
3. `квіт` заменено на `квітк`, `квітник`: «квіт» ловит «квітня», «квітень».
4. Добавлено `листя` целиком: корень `лист` ловит «листопада».
5. `зелен` — только в связках: одиночный корень ловит «Зеленський».
6. Для источников с тематическими тегами (КМДА — тег 19, Хмарочос — 317, 5445, 1705, 1644) словарь не применяется.

Новости о повреждении парков при обстрелах пропускаются в ленту (решение Заказчика 13.11.2026); стоп-слов на эту тему нет.

Технический урок для конвейера: в шаблоне `зелен\w* зон` класс `\w` не покрывает кириллицу (в JS и в ряде библиотек) — «зелених зон» не находится. Сравнивать по приведению к нижнему регистру и явным классам символов, с тестом на украинских строках.

## 7. Итоговая схема

**Схема:** белый список (раздел 4) → сбор по тематическим тегам и датам там, где они есть, лента целиком там, где нет → словарь и стоп-слова (раздел 6) только для источников без тегов → JSON в репозитории → статическая страница. Бэкенд не нужен; админка нужна только для скрытия карточек и правки словаря (по схеме «без будильника», `claude/06…`, раздел 7, п. 1). Параметры сбора — раздел 12.6.

Почему так:
- Не зависит от некоммерческих тарифов: источники разрешают использование со ссылкой, GDELT разрешает любое использование.
- Белый список закрывает требование «автопубликация» без риска посторонних тем: в ленту попадают только утверждённые издатели.
- Без ключей и секретов: нечему истекать, нечего хранить в публичном репозитории.
- Выборка по тегам вместо словаря убирает основной источник мусора: полнотекстовый поиск по `парк` у КМДА давал около 94 % нерелевантного (раздел 12.2).

Отброшено: NewsAPI.org (только разработка), GNews (сайт предприятия = коммерческое по их определению), Guardian (некоммерческое, фото платно), Суспільне, Слово і Діло, Еврокомиссия (раздел 4). NewsData.io — в резерве, если белый список окажется скуден.

### 12.3. GDELT: прогон не завершён

- Запрос `domain:kyivcity.gov.ua&timespan=1m&maxrecords=50` — HTTP 200, тело пустое (`{}`).
- Запрос `(парк OR сквер OR озеленення) sourcecountry:UP&timespan=1w` — HTTP 200, тело пустое.
- Все остальные попытки, включая контрольные `domain:bbc.com`, `domain:suspilne.media`, `park sourcecountry:UP`, — HTTP 429 с текстом «Please limit requests to one every 5 seconds…». Ошибка держалась при паузах 75 с, 90 с, 240 с, 330 с и спустя ~12 минут после последнего запроса.

Что из этого следует:
- Заявленный лимит «1 запрос в 5 секунд» на практике строже: после серии запросов адрес блокируется надолго. Контрольный запрос получить не удалось, поэтому **пустые ответы не доказывают, что домены не индексируются** — вопрос открыт.
- Для GitHub Actions это существенный риск: раннеры работают с общих адресов, которые другие проекты тоже используют для GDELT. Без повторных попыток с нарастающей паузой и кеша прошлой выдачи шаг синхронизации будет падать.
- Повторить прогон другим днём и с другого адреса. До тех пор GDELT — необязательный источник, выключенный в конфигурации (решение 2.1, п. 6).

### 12.6. Схема сбора (зафиксировано)

Исходная схема (версия 1.0): RSS там, где он есть, GDELT — там, где RSS нет. Прогон показал, что ленты есть у всех источников, поэтому исходное назначение GDELT отпало. Зафиксированная схема после решений 2.1:

1. **Сбор.** КМДА — HTML-выборка по тегу 19 с фильтром по датам. Київзеленбуд головний — WP REST по датам. The Conversation — Atom по 7 темам. Хмарочос — WP REST по тегам 317, 5445, 1705, 1644, только после письменного разрешения редакции. Для каждого источника RSS — запасной путь.
2. **Фильтр по словарю** — только для записей, пришедших запасным путём через RSS, где тематического тега нет. Выборки по тегам в словарь не прогоняются.
3. **Частота синхронизации** — 3 раза в сутки. При выборке по датам хватило бы раза в сутки, но запасной путь через RSS с окном около суток требует более частого опроса.
4. **GDELT** — необязательный источник мировых новостей, выключен в конфигурации; включается только после удачного повторного прогона, с повторными попытками с нарастающей паузой и кешем прошлой выдачи.
5. **Хранение и вывод.** Дубли убираются по адресу и нормализованному заголовку. Результат — JSON в репозитории. Блок показывает последние 6–8 карточек, скрытые редактором не выводятся. Ошибка источника не очищает ленту: прошлые карточки остаются, источник помечается недоступным.
6. **Фото источников не выводятся** ни по одному источнику; иллюстрация карточки — наша, по категории.
