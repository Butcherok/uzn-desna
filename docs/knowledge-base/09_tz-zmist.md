## 1. Оглавление ТЗ

**1. Назначение и границы**
1.1 Цель документа, источники правды, порядок внесения изменений
1.2 Состав версий 1–3 и что отложено (бриф, раздел 3)
1.3 Термины: карточка, лента, синхронизация, владелец, редактор, «данные / пусто / неизвестно»

**2. Пользователи и сценарии**
2.1 Житель района с телефона — найти телефон за два касания
2.2 Руководство и сотрудники на внутреннем показе, подтверждение карточек
2.3 Редактор без технических навыков
2.4 Владелец (Роман)
2.5 Целевые сценарии и действия по каждой роли

**3. Информационная архитектура**
3.1 Карта сайта, верхнее меню и подвал по версиям («Публічна інформація» — подпунктом «Про підприємство», блок «Підприємства мережі» в подвале)
3.2 URL-схема, языковые префиксы, канонические адреса, базовый путь GitHub Pages
3.3 Служебное поведение: 404, пустой блок, `noindex`

**4. Постраничные требования**
Единый шаблон на страницу: назначение → блоки → обязательные поля → источник данных → поведение при отсутствии данных → версия.
4.1 Головна · 4.2 Про підприємство (справка, руководство, структура) · 4.3 Публічна інформація (страница-указатель) · 4.4 Послуги · 4.5 Куди звертатися · 4.6 Контакти · 4.7 Новини: блок Facebook · 4.8 Новини: тематична стрічка · 4.9 Наші закупівлі (в1 — ссылка, в2 — карточки) · 4.10 Вакансії · 4.11 Зелені зони району · 4.12 Техніка та оренда · 4.13 English version · 4.14 Служебные страницы

**5. Контент и языки**
5.1 Правило двух языков: украинский по умолчанию и не меньше по объёму, явная пометка «тільки українською»
5.2 Правила текстов: заголовок карточки, обрезка до 200 символов, где отрывок источника допустим
5.3 Изображения: форматы, размеры, `alt`, права на использование, собственные иллюстрации категорий ленты
5.4 Персональные данные: что публикуется, как фиксируется согласие пяти карточек, e-mail скрыт от ботов

**6. Модель данных**
6.1 Общие правила: идентификаторы, даты, языковые поля, черновик/опубликовано, created/updated
6.2 Редактируемые сущности: Enterprise (название, реквизиты), Contact, Leader, Service, Scenario, Vacancy, PublicDoc, GreenZone, Equipment, StaticBlock
6.3 Синхронизируемые: FacebookPost, FeedItem, Tender, SyncState (курсоры, статус и время последнего успеха по источнику)
6.4 Доступ: User (роль, хэш пароля), Session, ActionLog
6.5 Три состояния выдачи: данные / пусто / неизвестно
6.6 Формат статических данных для фронта: JSON в репозитории, схема и её версия

**7. Интеграции и синхронизация**
7.1 Общая схема: GitHub Actions → JSON в репозиторий → сборка Pages; бэкенд нужен только админке
7.2 Facebook: права токена страницы, частота, фолбэк (встраиваемый блок или ручная новость)
7.3 Prozorro: запрос по ЄДРПОУ 04589645, поля карточки, частота
7.4 Тематическая лента: три источника, теги, 3 прогона в сутки, словарь только для RSS-пути, вытеснение в пределах 6–8 карточек, фото источников не выводятся
7.5 Отказоустойчивость: ошибка источника не очищает блок, TTL-кэш в БД, общий Promise, каталог ошибок, лог с маскированием
7.6 Расписания и лимиты бесплатных тарифов

**8. API бэкенда**
8.1 Общие правила: база, формат ошибок и кодов, CORS, ограничение частоты
8.2 Аутентификация и сессии
8.3 Эндпоинты контента по сущностям 6.2
8.4 Загрузка изображений и документов
8.5 Публикация: как правка редактора попадает в статическую сборку
8.6 Служебные: состояние сервиса, статусы синхронизаций
8.7 Поведение админки при спящем Render (ожидание до минуты)

**9. Роли и админка**
9.1 Матрица прав «владелец» / «редактор» по сущностям
9.2 Вход, хэш пароля, смена пароля, выход
9.3 Структура интерфейса: разделы, список, форма, предпросмотр
9.4 Требования UX для нетехнического редактора: подписи на украинском, без жаргона, подтверждения, понятные ошибки
9.5 Модерация импортированного: скрытие карточки ленты и поста Facebook
9.6 Резервные копии БД и порядок восстановления
9.7 Журнал действий

**10. Стек, структура кода и сборка**
10.1 Выбор сборщика (Astro + React или Vite + пререндер) — решение с причиной
10.2 Слои `components / domain / gateway / config`, строгий `tsconfig`
10.3 Структура репозитория и `docs/`
10.4 ESLint, Prettier, Vitest, pre-commit, `npm run ci` — с первого PR
10.5 Деплой: GitHub Pages, Render, переменные и секреты (репозиторий публичный)
10.6 Ветки, Conventional Commits, один PR на задачу, мерж только владельцем

**11. Нефункциональные требования**
11.1 Мобильная вёрстка первой, точки перелома, размеры тач-целей
11.2 Производительность: бюджет первого экрана, оптимизация изображений, целевые метрики
11.3 Доступность: WCAG 2.1 AA, контраст, клавиатура, семантика, `alt`
11.4 Индексация: `noindex` до решения руководства, порядок снятия, `sitemap`, метаданные
11.5 Безопасность: секреты вне репозитория, защита админки, заголовки
11.6 Надёжность: публичные страницы работают при спящем бэкенде, деградация блоков по отдельности
11.7 Браузеры и устройства

**12. Приёмка**
12.1 Критерий закрытия задачи: проверено разработчиком, зелёный CI, `docs/project-context.md` в том же PR, «принято»
12.2 Чек-лист версии 1 — постранично
12.3 Чек-лист версии 2 — синхронизации и админка
12.4 Чек-лист версии 3
12.5 Проверки перед официальным запуском: доступность, снятие `noindex`, согласия, резервные копии
12.6 Что проверяет Заказчик лично: чужие кабинеты, токен Facebook, доступы

**13. Приложения**
