## 3. Дефекты и риски

**Д1. `robots.txt` проекта не действует** (уже в `docs/findings.md`, 14.11.2026). Google: файл обязан лежать в корне хоста, в подкаталоге он недействителен; без доступа к корню — закрывать мета-тегом. На `github.io` корень — чужой репозиторий `butcherok.github.io`. Закрытие сейчас держится только на `<meta name="robots">`, и этого достаточно: Google должен обойти страницу, чтобы увидеть `noindex`, а обход не запрещён. **Вывод: до своего адреса текущее закрытие корректно; после переезда на свой хост `robots.txt` заработает.**

**Д2. Бэкенд: `Disallow: /` вместе с `noindex`.** Google: чтобы увидеть `noindex` в мета-теге или заголовке, страницу нужно обойти; если её блокирует `robots.txt`, тег не виден. Адрес, запрещённый к обходу, может попасть в индекс без содержимого, если на него есть ссылки — а на адрес Render ведёт страница `/admin` (решение 036). **Рекомендация:** на Render оставить `X-Robots-Tag: noindex, nofollow`, а `robots.txt` сделать разрешающим (или удалить). Это правка ТЗ 11.4 п. 5 — решение Заказчика.

**Д3. `description` длиннее предела ТЗ 11.4 (160):** «Послуги» 184, «Куди звертатися» 169, «Наші закупівлі» 161. Google лимита не ставит, обрезает по ширине экрана, — это дефект против ТЗ, не против Google. Проверки длины `title` (60) и `description` (160) в CI нет, поэтому превышение прошло приёмку. **Рекомендация:** сократить три текста и добавить проверку длины в `docs:check` или отдельный шаг сборки.

**Д4. У 404 есть `canonical` на `/404.html`.** GitHub Pages отдаёт этот файл на любой несуществующий адрес, и каждый такой адрес объявляет каноническим `/404.html`. Прямого запрета в документации Google не нашёл (не подтверждено), это наша рекомендация: на 404 `canonical` и `og:url` не выводить, `description` не повторять `title`.

**Д5. `lang="uk"` и `og:locale="uk_UA"` вшиты в `BaseLayout`.** Для версии 3 оболочке нужен параметр языка, иначе английские страницы получат украинскую разметку. Сейчас не дефект, а долг перед 4.13.

**Д6. Заголовок главной — «Головна — КП УЗН…».** Google советует описательные, не шаблонные `<title>` и строит заголовок ссылки в выдаче в том числе по ним. «Головна» не несёт смысла для поиска. **Рекомендация:** для главной — «КП УЗН Деснянського району — озеленення та догляд за зеленими насадженнями» (≤60 знаков: сверить при правке). Это отступление от формулы ТЗ 11.4 — решение Заказчика.

**Д7. Нет `og:image`** — заглушка ТЗ 11.4. Для поиска Google не нужен, для ссылки в Facebook и мессенджерах — да.

**Д8. Лента «Новини» — чужие публикации.** Политики спама Google относят к нарушениям перепубликацию чужого содержания из многих источников без добавленной ценности (формулировка сверена по вторичному источнику, страница политик Google существует). Карточки — заголовок, отрывок, ссылка, — страница как целое малоценна для поиска и может тянуть вниз оценку сайта. **Рекомендация:** при снятии закрытия оставить `/news/` с `noindex, follow` и не включать в `sitemap`. Решение Заказчика.

## 4. Адрес сайта — ключевой вопрос запуска

### 4.1. Что не работает на `butcherok.github.io/uzn-desna` (по документации)

| Возможность | Подкаталог `github.io` | Свой хост |
|---|---|---|
| Свой `robots.txt` со ссылкой на `sitemap` | Нет: файл только в корне хоста | Да |
| Название сайта в выдаче (`WebSite`) | Нет: Google не поддерживает подкаталоги | Да, домен или поддомен |
| Доменный ресурс Search Console (DNS) | Нет: DNS `github.io` не наш; доменное подтверждение публичных суффиксов не поддерживается (что `github.io` — публичный суффикс, по памяти, не проверено) | Да |
| Ресурс по префиксу URL | Да: мета-тег или HTML-файл | Да |
| `sitemap` | Да: в `/uzn-desna/` покрывает свой подкаталог, подаётся через Search Console | Да, в корне |
| HTTPS | Да | Да: GitHub Pages выпускает сертификат для своего поддомена по CNAME |

### 4.2. Варианты

1. **Рекомендую: `desna.kyivzelenbud.com` → GitHub Pages (CNAME у администратора DNS Київзеленбуду).** Адрес не меняется для людей и поиска: накопленные ссылки и позиции остаются, переадресации не нужны, бесплатно. Минус: зависим от администратора сети и от того, что старая WordPress-страница этого поддомена выключается. Старые адреса (`/about/info/`, `/about/people/`, `/about/publichna-informatsiya/`) отвечать перестанут — нужна карта соответствия и страницы-перенаправления по ТЗ 3.2 п. 8 (на Pages сервер-301 недоступен; meta refresh 0 с Google считает постоянной переадресацией).
2. **Новый поддомен сети** (например `uzn-desna.kyivzelenbud.com`) и 301 со старых страниц на WordPress. Тот же бесплатный путь, но старый сайт должен настроить переадресацию; Google рекомендует держать её не меньше 180 дней.
3. **Оставить `github.io`.** Работает всё, кроме строк «Нет» в таблице 4.1; дубль с чинною сторінкою остаётся. Только как временный.

Свой домен в зоне `.kyiv.ua` / `.com.ua` — платный, бюджет 0 грн, не рассматриваю.

- **П3.** `og:site_name` = «КП УЗН Деснянського району» — Google учитывает его при выборе названия сайта; ничего не стоит.
- **П4.** Формула `title` главной — Д6.
