# Доступ к админке: первый владелец и потерянный пароль

ТЗ 9.2, п. 2 и 5. Названия разделов Render и Atlas сверены с их документацией
20.11.2026 (задача 5б, решение 037). Первый запуск целиком, с кластером и
сервисом, — `docs/runbook-backend-deploy.md`. Пароль в открытом виде никуда не
вводится, кроме своего компьютера и формы входа. В чат, в git и в настройки Render попадает только хэш.

## Первый владелец

1. На своём компьютере, в папке репозитория (PowerShell):

   ```
   npm ci
   npm run hash-password
   ```

   Пароль вводится дважды, на экране не виден. Не короче 12 символов. Команда
   печатает строку вида `$2b$12$…` (60 знаков) — это хэш.

2. Render → сервис бэкенда → **Environment** → добавить:
   - `BOOTSTRAP_OWNER_LOGIN` — логин латиницей, 3–32 знака (`a–z`, `0–9`, `.`, `_`, `-`);
   - `BOOTSTRAP_OWNER_PASSWORD_HASH` — строка из шага 1;
   - `BOOTSTRAP_OWNER_DISPLAY_NAME` — имя для админки, необязательно.

   **Save and deploy**: Render перезапустит сервис на той же сборке. При
   первом создании сервиса из `render.yaml` эти значения Render спрашивает сам
   (`docs/runbook-backend-deploy.md`, шаг 6).

3. Render → **Logs**: должна появиться строка
   `Owner account created from BOOTSTRAP_* variables`.
   Если вместо неё `BOOTSTRAP_OWNER_PASSWORD_HASH is not a bcrypt hash` — в
   переменную попал не хэш. Повторить шаг 1.

4. Удалить переменные `BOOTSTRAP_*` из **Environment** → **Save and deploy**.
   Пока они стоят, при каждом запуске в журнале будет предупреждение
   `BOOTSTRAP_* variables are still set`.

5. Войти в админку с этим логином и паролем.

Как убедиться, что создание записано: в коллекции `action_log` есть запись
`action: "user.bootstrap"` (Atlas → кластер → **Browse Collections** → откроется Data Explorer). Хэш в неё не пишется.

## Владелец потерял пароль

Восстановления по почте нет (ТЗ 8.2, п. 5). Два пути.

**А. Заменить хэш в БД** — если владелец один и запись нужно сохранить:

1. `npm run hash-password` — новый хэш.
2. Atlas → кластер → **Browse Collections** (Data Explorer) → база `uzn` →
   `users` → запись владельца → значок карандаша → поле `passwordHash`
   заменить новым хэшем, `mustChangePassword` поставить `false` → **Update**.
   Подпись кнопки сохранения с документацией не сверена.
3. В той же базе, коллекция `sessions`: удалить записи с `userId` владельца.
   Так закроются входы, открытые до замены.
4. Войти с новым паролем.

Правка через Atlas идёт мимо сервера, поэтому в `action_log` её нет. Записать
дату и причину в `docs/project-context.md`, раздел «Открытые вопросы».

**Б. Повторный BOOTSTRAP** — только если в `users` нет других записей.
Бэкенд создаёт владельца, лишь когда учётных записей нет вовсе:

1. Atlas → `users` → удалить запись владельца; `sessions` — удалить все записи.
2. Выполнить раздел «Первый владелец» с шага 1.
3. Записи журнала (`action_log`) не удаляются: в них старый идентификатор
   владельца, по нему видна история.
