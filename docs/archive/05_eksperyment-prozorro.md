# Эксперимент: публичный API Prozorro по ЄДРПОУ 04589645

Версия 1.0 от 12.11.2026. Результат этапа 3 дорожной карты (`00_brief-sait-kp-uzn.md`, разделы 5.3 и 9). Закрывает пометку **[ПРОВЕРИТЬ]** в разделе 5.3 брифа.
Пометка **[ПРОВЕРИТЬ]** = не подтверждено, до использования в ТЗ нужна проверка.

**Как проверялось.** Документация: prozorro-api-docs.readthedocs.io (страницы feed, authentication, performance, tenders). Пробные запросы: 12.11.2026, 16:59–17:05, из браузера на компьютере Заказчика (киевский IP), без ключа и без cookies. Всего около 45 запросов.

**Что не проверено.** Запросы с сервера (Node.js на Render, без браузерных заголовков, зарубежный IP) не выполнялись: из облачной среды хост `public-api.prozorro.gov.ua` недоступен по настройкам сети сессии. Поведение при превышении лимита (ответ 429) не вызывалось намеренно.

---

## 1. Главное

1. Ключ не нужен. Чтение (GET) официального API работает без авторизации: так в документации и так в пробных запросах.
2. **Официальный API не умеет фильтровать по ЄДРПОУ.** Список `/tenders` — это лента изменений всей системы, отсортированная по времени изменения. Параметры `procuringEntity.identifier.id=`, `edrpou=`, `procuringEntity=` молча игнорируются: ответ 200, выдача та же.
3. Список закупок по ЄДРПОУ одним запросом отдаёт только внутренний API портала `prozorro.gov.ua/api/search/tenders`. Он работает без ключа, но в официальной документации не найден: это интерфейс самого сайта, он может измениться без предупреждения.
4. По ЄДРПОУ 04589645 портал находит «більше 1 000» закупок; последняя — UA-2026-11-12-006460-a от 12.11.2026. Данные живые.

## 2. Официальный API

Адрес: `https://public-api.prozorro.gov.ua/api/2.5/`. Разделы: `tenders`, `plans`, `contracts`, `agreements`, `frameworks` — все ответили 200.

### 2.1. Список (лента)

Ответ: `data` (массив), `next_page` и `prev_page` (в каждом `offset`, `path`, `uri`).
Элемент по умолчанию: только `id` (32 hex) и `dateModified`.

Параметры (документация, страница feed; проверено запросами, кроме `mode`):
- `limit`: по умолчанию 100, максимум 1000. Запрос `limit=1001` вернул 1000.
- `offset`: курсор из `next_page.offset`. Мусорное значение — 404 с `errors`.
- `descending=1`: от новых к старым. Без него лента идёт с 23.02.2015.
- `opt_fields`: дополнительные поля через запятую.
- `mode`: `test`, `_all_`; не проверялся.

Что реально вернул `opt_fields`:
- tenders: `procuringEntity` (целиком, с `identifier.id`), `tenderID`, `status`, `procurementMethodType`, `dateCreated`. Запрошенные `title`, `value`, `items`, `mainProcurementCategory` не вернулись.
- plans: `procuringEntity`, `planID`, `status`. `budget`, `classification` не вернулись.
- contracts: `contractID`, `status`. `buyer`, `procuringEntity`, `value`, `suppliers` не вернулись — заказчика из ленты договоров не узнать.

Объём ленты: 1000 последних изменений тендеров покрыли 23 минуты (16:36–16:59, четверг). Страница с `procuringEntity` — 1,79 МБ без сжатия (ответ идёт в gzip), время ответа 0,5 с. Среди этих 1000 записей закупок предприятия 0.

### 2.2. Одна закупка

`GET /tenders/{id}` — только по 32-символьному `id`. По номеру `UA-…` — 404.
Ответ: `data` и `config`. Проверено на закупке предприятия (`id` 85f31f089cd94eaebb20e35ff5818eb9), размер 104 КБ:
- `tenderID`, `title`, `status`, `procurementMethodType`, `mainProcurementCategory`
- `value`: `amount`, `currency`, `valueAddedTaxIncluded`
- `procuringEntity.identifier`: `scheme` UA-EDR, `id` 04589645, `legalName`, `legalName_en`
- `tenderPeriod`: `startDate`, `endDate`; `dateCreated`, `dateModified`
- `items[]` с `classification` (ДК021), `documents[]`, `lots`, `milestones`, `criteria`

Ошибки: JSON `{"status":"error","errors":[{"location","name","description"}]}`.

### 2.3. Лимиты

- Документация, страница feed: 140 запросов в секунду на публичных адресах.
- Документация, страница performance: «агрессивным» IP ограничивают скорость, ответ 429; клиент повторяет запрос, увеличивая паузу.
- Документация, страница tenders: безопасная частота синхронизации — раз в 5 минут.
- В заголовках ответа сведений о лимите нет.
- Запрос с другого домена (со страницы prozorro.gov.ua) прошёл. Разрешён ли любой домен — **[ПРОВЕРИТЬ]**; для синхронизации на бэкенде не важно.

## 3. Поиск портала (не документирован)

`POST https://prozorro.gov.ua/api/search/tenders?buyer[0]=04589645`, тело пустое. GET — 405.

Ответ: `page`, `per_page`, `total`, `data`. Элемент:
- `tenderID`, `title`, `status`
- `value`: `amount`, `currency`, `valueAddedTaxIncluded`
- `tenderPeriod.endDate`
- `procuringEntity`: `name`, `name_en`, `identifier.legalName` (кода ЄДРПОУ в выдаче нет)

Поля `id` и даты публикации в списке нет. Дата читается из номера `UA-ГГГГ-ММ-ДД-…`. Ссылка на закупку: `https://prozorro.gov.ua/tender/{tenderID}`.

Проверено:
- Страница — 20 записей, `per_page=100` игнорируется. `page` от 1 до 50; `page=0` и `page=600` — 422.
- `total` упирается в 1000, настоящего количества не показывает. Страница 50 заканчивается закупкой от 27.03.2023: доступно примерно 3,5 года истории.
- Порядок по умолчанию — от новых к старым.
- Фильтр `status[0]=active.tendering` работает: 2 закупки.
- `/api/search/contracts` и `/api/search/plans` с тем же `buyer[0]` отвечают 200 (договоры: `contractID`, `value`, `suppliers`, `buyer`, `status`; планы: `planID`, `budget`, `status`, `tender`).
- Заголовки `x-ratelimit-limit: 60`, `x-ratelimit-remaining`. Окно в заголовке не указано; «60 в минуту» — из стороннего источника **[ПРОВЕРИТЬ]**.
- Связка с официальным API: `GET /api/tenders/{tenderID}/summary` отдаёт `id`, по нему открывается официальная карточка.

**[ПРОВЕРИТЬ]** до ТЗ: отвечает ли поиск портала серверу на Render (без заголовков браузера, зарубежный IP).

## 4. Варианты для «Наші закупівлі» версии 2

| | А. Поиск портала | Б. Официальная лента | В. А + официальная карточка |
|---|---|---|---|
| Запросов на синхронизацию | 1 на 20 последних закупок | Все изменения системы с прошлого раза: около 1000 записей за 23 минуты в рабочее время | 1 + по 2 на каждую новую закупку |
| История | До 1000 последних | Только с момента запуска; прошлое — обход ленты с 2015 года | Как в А |
| Поля для карточки | Название, номер, статус, сумма, срок подачи | Названия и суммы в ленте нет, нужен запрос на каждую закупку | Плюс вид закупки, код ДК021, документы |
| Документирован | Нет | Да | Частично |
| Нагрузка на Render Free | Минимальная | Большая: десятки страниц по 1,8 МБ в сутки (оценка по одному замеру) | Малая |

**Рекомендация: А.** Причина: один запрос даёт всё, что нужно карточке; вариант Б ради «официальности» тянет всю ленту страны и всё равно не даёт истории. Риск недокументированного адреса закрывается тем, что уже решено: ссылка на Prozorro по ЄДРПОУ остаётся на странице (`claude/04_vymohy.md`, раздел 6, п. 7), а при сбое синхронизации сайт показывает последние сохранённые данные (бриф, раздел 5.1, п. 3) и отличает «ошибка» от «пусто» (бриф, раздел 6). Решение — в ТЗ.
