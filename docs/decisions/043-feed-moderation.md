# 043: Модерация ленты «Новини галузі»

Дата: 2026-11-22
Статус: принято

## Вопрос

Как редактор скрывает чужую публикацию из ленты (ТЗ 9.5) так, чтобы скрытие
пережило синхронизацию, попало на сайт через обычную публикацию и не дало
править чужой текст. Карточки ленты в БД не хранятся: их пишет синхронизация в
ветку `sync-data` (ТЗ 6.3, решение 023).

## Решение

Ответы Заказчика 22.11.2026 — «по рекомендациям»; ТЗ 3.35.

1. **Решение в БД, карточка — нет.** Коллекция `moderation`: `_id` — `urlKey`,
   `hidden`, `updatedAt`, `updatedBy`. Возврат снимает `hidden`, запись остаётся:
   иначе возврат не попал бы в счётчик неопубликованных правок.
2. **Выгрузка.** `GET /export` отдаёт десятый файл `moderation.json` (конверт
   6.6): только скрытые, `{ urlKey, hiddenAt }`, по возрастанию ключа — порядок
   не зависит от БД, пустой коммит в `content-data` не делается. Файл есть и в
   `main` (пустой): сборка без `content-data` и `data:check` его находят.
   Перечень файлов в `publish-content.yml` сверяется с `EXPORT_FILES` тестом.
3. **Сборка.** `feedCards(file, limit, hidden)` отбрасывает скрытые до отбора
   последних: место скрытой занимает следующая из 40 сохранённых, на «Новини»
   остаётся 8, на главной 3. Файл ленты не меняется: признак `hidden` в нём
   переписала бы следующая синхронизация.
4. **Чтение ленты в админке.** Бэкенд берёт тот же `data/sync/feed.json` ветки
   `sync-data` с `raw.githubusercontent.com` (публичный репозиторий, без
   токена), кэш 60 с и общий Promise (ТЗ 7.5, п. 4). Сбой — прежняя копия и
   `state: unknown` (6.5); первый сбой — пустой список с сообщением.
5. **API.** `GET /feed` — карточки, видимые по дате, затем скрытые, у каждой
   место после публикации (`home`, `news`, `reserve`). `POST /feed/hidden` —
   `{ urlKey, hidden }` в теле: в ключе косые черты, в адресе они ломаются на
   прокси. Повтор того же решения ничего не меняет и в журнал не пишется.
   Скрыть можно только карточку из ленты (404), вернуть — всегда.
6. **Админка.** Раздел «Новини галузі» для владельца и редактора (9.1):
   «Приховати» без подтверждения, сообщение с «Повернути» и указанием на
   «Опублікувати зміни»; счётчик в полосе растёт. Публикация сама не
   запускается: несколько скрытий — одна публикация.
7. **Журнал.** `feed.hide` / `feed.show`, сущность `feed`, идентификатор —
   `urlKey`, в деталях заголовок и источник.

## Отброшено

- Признак `hidden` в `feed.json` (ТЗ 6.3, п. 4 в прежней редакции): файл пишет
  синхронизация, признак терялся бы при каждом прогоне.
- Эндпоинты `/moderation/{kind}/{key}` из ТЗ 8.3 в прежней редакции: ключ с
  косыми чертами в адресе; вида записи нет — Facebook исключён (решение 029).
- Выбор категории (ТЗ 9.5, п. 4 в прежней редакции): категорий нет (решение 031).
- Автоматическая публикация после скрытия: каждое скрытие — 3–5 минут прогона.
- Чтение ленты через API GitHub с токеном: токену публикации не нужны права на
  содержимое, а публичный файл читается без него.

## Последствия

- Набор файлов выгрузки и `EXPORT_FILES` сборки меняются вместе. Пока Render не
  выложил новую версию (~7 мин после слияния), публикация падает с
  `SCHEMA_MISMATCH`, сайт не трогается; после выкладки — проходит.
- В `moderation` копятся ключи вытесненных из ленты карточек: десятки строк в
  год, на сборку не влияют.
- Резервная копия (9.6) включает коллекцию `moderation`.
