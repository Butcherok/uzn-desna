# 029: Блока Facebook на сайте нет

Дата: 2026-11-20
Статус: принято

## Вопрос

Делать ли раздел «Новини підприємства» из постов страницы Facebook (ТЗ 4.7, 7.2;
задача 4б), если доступа к странице у разработчика не будет.

## Решение

Раздел исключён (решение Заказчика 20.11.2026: «доступа к фейсбук не будет,
убираем этот раздел»). Страница «Новини» состоит из ленты «Новини галузі»
(ТЗ 4.8). Страница Facebook предприятия остаётся ссылкой в подвале (ТЗ 3.1).
ТЗ 3.23: разделы 4.7 и 7.2 помечены «Исключено» с сохранением номеров; из 6.3,
7.1, 7.5, 7.6, 8, 9.5, 10.3, 11.6, 12.3, 12.5, 13.1 убраны `FacebookPost`,
`facebook.json`, токен, секреты Meta, ручная новость и модерация постов;
заглушки 20, 21, 38 закрыты.

## Отброшено

- **Graph API без токена.** Анонимного чтения нет; чтение чужой страницы
  (Page Public Content Access) требует проверки приложения и верификации бизнеса
  (отчёт 07, раздел 1; сверено с документацией Meta 20.11.2026).
- **Сбор страницы программой (парсинг).** Условия Meta запрещают
  автоматический сбор данных без разрешения, в том числе без входа в аккаунт;
  у Facebook защита от ботов, с раннеров GitHub это ломалось бы так же, как с
  КМДА (последнее не проверялось).
- **Page Plugin.** Дизайн Facebook и сторонний скрипт в странице — против
  требования к скорости первого экрана (отчёт 07, раздел 7).

## Последствия

- Кода блока Facebook не было (задача 4б не начиналась) — удалять в коде нечего,
  кроме комментария страницы «Новини».
- Секретов `FB_PAGE_TOKEN`, `FB_PAGE_ID` и приложения Meta не будет;
  `docs/runbook-facebook-token.md` не пишется.
- Пункт 4 очереди версии 2 закрывается частью 4а и правкой карточек (решение 031).
- Вернуть блок можно только новым решением Заказчика при появлении доступа к
  странице; план прогона — отчёт 07, раздел 8.
