# 046: Предпросмотр карточек в админке (пункт 5з)

Дата: 2026-11-23
Статус: принято (ответ Заказчика 23.11.2026: «делай всё по рекомендациям, главное
чтобы было комфортно и интуитивно понятно любому человеку с улицы»)

## Вопрос

Как выполнить ТЗ 9.3 «карточка рисуется в админке теми же React-компонентами, что
на сайте» (решение 040, п. 1): где показывать образец, в каких разделах, на каком
языке, что делать с записью, которой на сайте сейчас нет, и как перевести карточки
сайта на React, не добавив JavaScript на публичные страницы.

## Решение

Ответы Заказчика 23.11.2026 (правка ТЗ 3.36):

1. **Разделы с образцом — пять:** Послуги, Керівництво, Вакансії, Публічна
   інформація (карточки) и Контакти (строка с крупной кнопкой-телефоном). В «Куди
   звертатися», «Тексти сторінок» и «Підприємство» образца нет: на сайте это строка,
   абзац или таблица, а текст и так виден в поле.
2. **Место:** на телефоне и планшете — под полями, перед кнопками; на широком
   экране — справа от формы, не уезжает при прокрутке. Образец меняется сразу, по
   мере ввода, без отдельной кнопки.
3. **Язык — открытой закладки.** Пустой английский — надпись «Англійською ще не
   заповнено» вместо карточки; заполнено частично — карточка из заполненного и
   перечень незаполненных полей.
4. **Запись, которой на сайте не видно, — с причиной над образцом:** чернетка,
   номер не отмечен «Номер перевірено», прошёл срок «Показувати до», документ не
   попадает в блоки карточек, фото без описания (на сайте не выводится, ТЗ 11.3).
5. **Карточки — React-компоненты, превращаемые в HTML при сборке, без интеграции
   `@astrojs/react`** (уточнение решения 004). Опыт 23.11.2026: с интеграцией в
   сборку попадает `client.*.js` 220 КБ, на который не ссылается ни одна страница;
   без неё набор файлов сборки тот же, что на `main`, JavaScript на страницах 0 КБ.
6. **Два PR:** первый переводит карточки сайта на React (проверка — сайт совпадает
   с `main`), второй добавляет образец в админку.

Решения разработчика:

- **Компоненты — `site/src/components/cards/`**, функция `renderStatic`
  (`renderToStaticMarkup`) — там же. Страница Astro выводит результат
  `<Fragment set:html>`. `PhoneLink.astro`, `PhoneInline.astro`, `DocLink.astro`
  остались обёртками над React-компонентами: места вызова не менялись. Компоненты
  принимают готовые строки и адреса: фото сайта — WebP из `getImage` (те же
  размеры и плотности, что давал `<Image>`), админки — загруженный файл; адрес
  документа находит слой gateway (`docTarget`).
- **Отличия HTML от `main` — только запись, не содержимое:** апостроф `&#x27;`
  вместо `&#39;` и имя атрибута `srcSet` вместо `srcset` (имена атрибутов HTML не
  зависят от регистра). Остальные 42 файла сборки совпадают побайтно; сверка —
  скриптом по всем файлам сборки (описание PR).
- **Образец в админке — в теневом DOM** с таблицей стилей сайта: у админки свои
  классы `.card` и `.card__text`, и без изоляции карточка выглядела бы не как на
  сайте. Стили подключаются файлом (`style-src 'self'`), встроенных стилей нет.
- **Образец не нажимается** (`inert`): телефон и ссылки в нём не срабатывают, и
  случайное нажатие не уводит со страницы с несохранёнными правками. Экранный
  диктор его пропускает — содержимое то же, что в полях формы; заголовок образца
  и причины скрытия остаются доступными.
- **Записи на сайте нет совсем** (чернетка, прошёл срок, номер не проверен,
  документ вне блоков карточек) — над образцом «Зараз цієї картки на сайті немає»
  и пунктирная рамка: карточка не выдаёт себя за видимую. Частичное (фото без
  описания) — только причиной, рамка обычная.
- **Правило слоёв ESLint для components** запрещает только gateway: компонент
  может собирать другие компоненты (образец рисует карточки сайта). Слою domain
  по-прежнему нельзя ни gateway, ни components.
- **Vite админки берёт её `tsconfig.json` для всех файлов** (`tsconfig` в
  `admin/vite.config.ts`): иначе для карточек он читал `site/tsconfig.json`, а тот
  ссылается на Astro, которого на Render нет. Найдено сборкой командой из
  `render.yaml` в чистой копии.
- **Правила видимости — одни для сайта и админки:** админка берёт функции слоя
  domain сайта (`isVisible` вакансии, `isProcurement` документа), а не копирует их.

## Отброшено

- **Интеграция `@astrojs/react`** — лишний файл 220 КБ в сборке (решение 004).
- **Копия вёрстки карточек в админке** — нарушает ТЗ 9.3 и 10.2.
- **Образец по кнопке «Показати»** — лишнее действие; человек не знает, что его нужно
  нажать.
- **Образец всей страницы** — сайт статический, страница появляется только после
  сборки (ТЗ 9.3).
- **Образец только на украинском** — длину английского текста не проверить до версии 3.
- **Один PR** — перевод сайта и админка вместе: если что-то сломается, не видно где.

## Последствия

- `render.yaml`, `buildFilter`: админка теперь собирает файлы `site/src/components/cards/`,
  `site/src/domain/` и `site/src/styles/components.css` — эти пути добавляются во
  втором PR вместе с импортом.
- Новая карточка сайта, которую правит админка, делается React-компонентом в `cards/`.
- Тест `cards.test.ts` закрепляет разметку: правка карточки видна на сайте и в
  админке сразу.
