# 045: Резервная копия БД

Дата: 2026-11-22
Статус: принято

## Вопрос

Как делать резервную копию БД при бюджете 0 грн (ТЗ 9.6): бесплатных копий у
Atlas нет, репозиторий и артефакты прогонов публичны, а дамп содержит хэши
паролей и данные сотрудников. И как доказать, что из копии поднимается рабочая
БД, а не только что «файл создался».

## Решение

Ответы Заказчика 22.11.2026 — «по рекомендациям»; ТЗ 3.35, 9.6.

1. **Рабочий процесс `backup`** — 1-го числа в 00:43 UTC и `workflow_dispatch`.
   `mongodump --db=uzn --excludeCollection=sessions --gzip --archive` из образа
   `mongo:8` (утилиты в нём уже есть, ставить нечего).
2. **Доступ только на чтение.** Пользователь Atlas `uzn-backup`, право `read`
   на базу `uzn`; строка — секрет Actions `BACKUP_MONGODB_URI`. Пароль задаёт
   Заказчик: агенту вводить пароли запрещено. Ключ Render не используется.
3. **Шифрование `age` на два получателя**: открытый ключ владельца
   (`.github/backup-recipients.txt`, создан владельцем 22.11.2026) и
   одноразовый ключ прогона. Нешифрованный дамп удаляется сразу после
   шифрования; в артефакт идёт только `.age`.
4. **Проверка в каждом прогоне.** Одноразовым ключом файл расшифровывается,
   `mongorestore` поднимает его в служебной `mongo:8`, число документов по
   коллекциям сверяется с журналом `mongodump`
   (`scripts/src/backup/counts.ts`). Расхождение или пустой журнал — прогон
   красный (`BACKUP_MISMATCH`). Таблица — в отчёте прогона: это и есть сверка
   «с `/system/info`» из прежней редакции 9.6. Одноразовый ключ удаляется до
   выгрузки артефакта.
5. **Артефакт** — 90 дней (максимум публичного репозитория), без сжатия
   поверх `gzip`.
6. **Кнопка в админке** — раздел «Резервні копії» (владелец): `POST /backup`
   запускает рабочий процесс тем же токеном, что и публикацию; номер прогона
   пишется в журнал (`backup.start`) и по нему `GET /backup` показывает
   состояние. Второй запуск при идущем — 409.
7. **Проверка ключа владельца** — один раз, по `docs/runbook-restore.md`:
   владелец расшифровывает настоящую копию своим ключом.

## Отброшено

- Платные копии Atlas (0,10 $ в день, нужна карта; отчёт 06).
- Шифрование симметричным паролем в секрете Actions: пароль жил бы рядом с
  копией, и любой с правом на секреты читал бы все копии.
- Хранение копии в репозитории или ветке: история git не удаляется.
- Восстановление проверкой «раз при запуске»: копия, которая не
  поднимается, обнаружилась бы только при аварии.
- Отдельная коллекция под прогоны копий: номер прогона уже есть в журнале.

## Последствия

- Без секрета `BACKUP_MONGODB_URI` прогон красный с `BACKUP_NOT_CONFIGURED`.
- Смена ключа владельца — правка `.github/backup-recipients.txt` PR-ом; старые
  копии остаются под старым ключом.
- Восстановление делает владелец на своём компьютере; журнал действий его не
  видит (его заменяет копия) — оно записывается в журнал решений ТЗ (13.3).
