# 048: запасной запуск синхронизации — Prozorro только при молчащем расписании

Дата: 2026-11-23
Статус: принято (уточняет решение 033, п. 2)

## Вопрос

Прогон чек-листа 12.3 (23.11.2026, дефект Д2): расписание `Sync external`
работает, но приходит на 5–8 часов позже, а ежедневный `kick-sync` из `Deploy`
(решение 033) всегда запускает Prozorro. В итоге Prozorro опрашивается дважды в
сутки, а ТЗ 7.3, п. 3 говорит об одном утреннем опросе.

## Решение

Ответ Заказчика 23.11.2026 — вариант (а), «по рекомендации»: запасной запуск
берёт только ленту. Чтобы не потерять смысл решения 033 (данные обновляются и
при молчащем расписании), `kick-sync` перед запуском смотрит журнал Actions: если
за 30 часов нет ни одного прогона `Sync external` с событием `schedule`, он
запускает `prozorro feed`, иначе — `feed`. Ошибка запроса к журналу считается
молчанием расписания (лишний опрос лучше пропущенного).

## Отброшено

- **(а) без условия** — при молчащем расписании (как 19–20.11.2026) Prozorro
  перестал бы обновляться совсем.
- **(б) Prozorro только в `kick-sync`** — утренний опрос по времени `Deploy`
  (22:20 UTC и позже), ТЗ 7.3 пришлось бы переписать.
- **(в) оставить два опроса** — расходится с ТЗ 7.3, п. 3.

## Последствия

- Опоздание расписания GitHub не лечится: «утренний» прогон Prozorro приходит
  днём. Это свойство расписания GitHub, а не кода.
- Проверка — журнал `Deploy` по расписанию: строка «Прогонов Sync external по
  расписанию за 30 ч: N; шаги: …» и шаги запущенного `Sync external`.
