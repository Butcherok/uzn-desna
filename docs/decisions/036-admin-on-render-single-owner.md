# 036: Админка отдаётся с Render; учётная запись одна — владелец

Дата: 2026-11-20
Статус: принято (решения Заказчика 20.11.2026)

## Вопрос

ТЗ 8 до версии 3.27 клало интерфейс админки в статическую сборку на GitHub
Pages, а API — на Render. Это разные сайты (`github.io` входит в Public Suffix
List), поэтому cookie сессии `SameSite=Lax` в запросах админки к API не
отправляется, а `SameSite=None` — сторонняя cookie, которую Safari блокирует
целиком (`docs/findings.md`, «Межсайтовая cookie», закрыто). Второй вопрос —
сколько учётных записей заводить в 5б: в админке работает один человек, но
неясно было, владелец это или отдельный редактор (ТЗ 6.4, заглушка 33).

## Решение

1. **Интерфейс админки отдаёт сам сервис на Render**, с того же адреса, что и
   API. Cookie сессии своя (first-party): вход работает во всех браузерах,
   включая Safari. Изменяющие запросы админки к API — с того же адреса.
2. **Страница `/admin` на Pages — будильник.** Без формы входа: при открытии
   шлёт `GET /api/v1/health`, через 3 с без ответа показывает «Сервіс
   прокидається, це займає до хвилини» (ТЗ 8.7) и, когда сервис ответил,
   переводит браузер на адрес админки на Render.
3. **Учётная запись одна — владелец (Заказчик).** Отдельного редактора нет.
   Роль `editor` остаётся в модели и в матрице ТЗ 9.1: если Заказчик решит
   завести редактора, запись заводит владелец, код менять не нужно.

Правится ТЗ 3.27: вступление 8, 8.1 п. 5, 8.2 пп. 1–2, 8.7, 4.14, 6.4, таблица
10.1 (строка админки), 10.5 («Бэкенд»); заглушка 33 закрыта.

## Отброшено

- **Админка на Pages и `SameSite=None`** — на iPhone и Mac в Safari вход не
  заработает: сторонние cookie заблокированы с Safari 13.1.
- **Токен в памяти страницы вместо cookie** — работает везде, но перезагрузка
  страницы требует нового входа, а `localStorage` ТЗ 8.2 запрещает.
- **Свой домен для сайта и API** — платный, вне бюджета 0 грн.
- **Отдельный редактор в 5б** — Заказчик работает в админке сам.

## Последствия

- Для 5б: в Render ничего сверх решения 037 не нужно. `SITE_ORIGIN` остаётся
  адресом Pages: CORS нужен только будильнику (`GET /health`). Cookie
  `__Host-uzn_sid; Secure; SameSite=Lax` годится как есть.
- Для 5г: сервер начинает отдавать собранный интерфейс админки; в список
  разрешённых `Origin` изменяющих запросов (`app.ts`, хук защиты) добавляется
  собственный адрес сервиса — его Render задаёт сам в `RENDER_EXTERNAL_URL`.
  Сейчас запрос с `Origin` адреса Render отклонился бы.
- Для 5г: будильник на Pages знает адрес сервиса из `PUBLIC_API_BASE`
  (ТЗ 10.5: не секрет). Ожидание пробуждения больше не накладывается на набор
  пароля: форма входа открывается после пробуждения.
- Для 5б: заводится одна запись — владелец, через `BOOTSTRAP_*`.
