# 037: Живой запуск на Render и Atlas (пункт 5б)

Дата: 2026-11-20
Статус: принято; значения, помеченные «живой прогон», подтверждаются после запуска

## Вопрос

Как настроить сервис на Render Free и кластер Atlas Free для сервера из
`server/` (решение 035): ручная настройка или файл, откуда собирать в
монорепозитории npm workspaces, какое значение `TRUST_PROXY`, как проверять
состояние и как замерить вход с bcrypt cost 12 на бесплатном процессоре.

## Решение

Сверено с документацией Render и MongoDB 20.11.2026 (источники — в PR):

- **`render.yaml` (Blueprint)**, а не ручная настройка: настройки видны в
  репозитории и проверяются в PR. Секреты — `sync: false`, Render спрашивает их
  только при создании из файла.
- **Тариф `free`:** 512 МБ памяти, 0,1 процессора; засыпает через 15 минут без
  входящего трафика, просыпается около минуты; 750 часов в месяц на рабочее
  пространство; shell нет; пока сервис спит, `/robots.txt` отвечает сам Render.
- **Регион `frankfurt`**, ближайший к Киеву из пяти.
- **Сборка из корня репозитория, без `rootDir`.** Render не отдаёт сборке файлы
  вне `rootDir`, а серверу нужны `shared/` и корневой `package-lock.json`.
  Команда ставит только зависимости сервера и корня:
  `npm ci --include=dev --workspace=server --include-workspace-root`.
  Проверено в чистой копии без `.git` при `NODE_ENV=production HUSKY=0`:
  237 пакетов против 487 полной установки, Astro не ставится, сборка и запуск
  проходят. `--include=dev` нужен, потому что `NODE_ENV=production` действует
  и при сборке, а `esbuild` — devDependency.
- **Запуск** `node --enable-source-maps server/dist/index.js`, без `npm`.
- **Версия Node.js** — из `.nvmrc` в корне (26): у Render порядок `NODE_VERSION`
  → `.node-version` → `.nvmrc` → `engines`. Номер в журнале сборки — живой прогон.
- **`PORT`** задаёт Render (по умолчанию 10000); сервер слушает `0.0.0.0:$PORT`.
- **Проверка состояния** `healthCheckPath: /api/v1/health`. Ответ 200 и при
  недоступной БД (`dbConnected: false`), поэтому пауза Atlas не вызывает
  перезапусков. У маршрута свой предел — 120 запросов в минуту на адрес вместо общих 60 — и нет записи каждого запроса в журнал: Render опрашивает его каждые несколько секунд. Совсем без предела нельзя: каждый запрос пингует Atlas.
- **Версия сборки** — `RENDER_GIT_COMMIT` (полный SHA, Render задаёт и при
  сборке, и при работе); в `/health` — первые 7 знаков.
- **`autoDeployTrigger: checksPass`** — выкладка только после зелёных проверок
  коммита в `main`. `buildFilter` — только `server/`, `shared/`, корневые
  `package*.json`, `.nvmrc`, `render.yaml`.
- **`TRUST_PROXY=1` — предварительно.** В документации Render число прокси и
  заголовок адреса клиента не описаны; документация говорит лишь, что весь
  входящий трафик идёт через Cloudflare. По сообщениям сообщества Render
  дописывает в `X-Forwarded-For` один адрес и не чистит присланный клиентом.
  При `1` сервер берёт последний адрес списка — подделка левой части не
  помогает (проверено на сборке: `X-Forwarded-For: 1.2.3.4, 9.9.9.9` → `9.9.9.9`).
  Окончательное значение — живой прогон (`docs/runbook-backend-deploy.md`, шаг 6).
- **Замер входа:** ответ `/auth/login` несёт `Server-Timing: pw;dur=<мс>` —
  время одной проверки bcrypt. Есть и у отказа; время не зависит от логина.
- **Atlas Free:** MongoDB 8.0 (как в CI, `mongo:8`); 0,5 ГБ; 100 операций в
  секунду; 500 соединений; пауза после 30 дней без соединений. Пользователь БД
  — с привилегией `readWrite` только на базу `uzn` («Specific Privileges»).
  Список доступа `0.0.0.0/0` (ТЗ 10.5, п. 3); Atlas пришлёт об этом письмо.

## Отброшено

- **`rootDir: server`** — сборка не увидит `shared/` и lock-файл.
- **Полная установка `npm ci`** — ставит сайт (Astro, sharp) ради сервера:
  дольше сборка и больше минут сборки бесплатного тарифа.
- **`startCommand: npm start --workspace server`** — лишний процесс npm между
  Render и сервером на пути сигнала остановки.
- **`TRUST_PROXY` по заголовкам Cloudflare (`CF-Connecting-IP`)** — Render их
  не документирует.
- **Ручная настройка в кабинете** — не видна в репозитории, расходится с ним.

## Последствия

- Если вход на Render дольше 2–3 с, решение 035 предлагает два пути: обычный
  `bcrypt` (нативный модуль) или меньший cost; ТЗ 6.4 требует 12. Решает Заказчик
  по замеру.
- Пока сервис не спит, проверки состояния каждые несколько секунд пингуют Atlas.
  Не дают ли они Render заснуть, в документации не сказано — смотрится в журнале
  событий сервиса после 15 минут без запросов. Даже без сна 720 часов в месяц
  укладываются в 750.
- Адрес сервиса (заглушка 34) и логин владельца (заглушка 35) появляются после
  создания сервиса и закрываются в ТЗ следующей правкой.
