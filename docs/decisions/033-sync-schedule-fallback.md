# 033: Расписание синхронизации — минута 43 и запасной запуск из `Deploy`

Дата: 2026-11-20
Статус: принято

## Вопрос

С 19.11.2026 (слияние PR #29) по 20.11.2026 11:25 UTC ни один запуск
`Sync external` по расписанию не состоялся — ни на 05:10, ни на 11:10, ни на
17:10 UTC; в журнале Actions их нет вовсе, ни красных, ни пропущенных. Рабочий
процесс включён. `Deploy` по своему расписанию при этом запускается, с
опозданием до 5 ч. Заказчик 20.11.2026: «запасной путь сразу делаем».

## Решение

1. **Минута 43 вместо 10:** `43 4`, `43 10`, `43 16` UTC. Правка файла заново
   регистрирует расписание у GitHub, а запуски не в начале часа GitHub
   задерживает и отбрасывает реже (по документации GitHub — нагрузка выше
   в начале часа). Причина молчания нашего расписания не установлена.
2. **Запасной запуск:** у `Deploy` по расписанию (раз в сутки, 22:20 UTC)
   появилась работа `kick-sync` — она запускает `Sync external` с шагами
   `prozorro feed`. Синхронизация, если данные изменились, сама запустит
   `Deploy` (решение 023). Так данные обновляются не реже раза в сутки даже при
   молчащем расписании синхронизации. Права `actions: write` — только у этой
   работы.

## Отброшено

- **Внешний будильник** (cron-job.org и т. п. с токеном GitHub) — токен с правом
  запуска у третьей стороны и противоречит схеме «без будильника» (отчёт 06,
  раздел 7, п. 1).
- **Слить синхронизацию в `Deploy`** — смешивает сборку с записью в
  `sync-data`; права на запись понадобились бы сборке.
- **Запускать синхронизацию из `Lighthouse`** — тот идёт после каждой
  публикации, получился бы круг «синхронизация → публикация → замер →
  синхронизация».

## Последствия

- Prozorro в запасном прогоне читается и ночью, помимо утреннего прогона по
  расписанию (ТЗ 7.3, п. 3 говорит об утреннем): один лишний запрос в сутки,
  лимит портала — 60 (решение 023).
- Проверка — журнал Actions: запуски `Sync external` с событием `schedule`
  (минута 43) и `workflow_dispatch` от `github-actions` после ночного `Deploy`.
- Если и минута 43 молчит, а `kick-sync` работает, синхронизация остаётся
  раз в сутки; чаще — только новым решением.
