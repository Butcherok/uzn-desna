# 040: Интерфейс админки (пункт 5г)

Дата: 2026-11-21
Статус: принято (ответ Заказчика 21.11.2026: «все пункты по рекомендациям»)

## Вопрос

Как построить интерфейс админки ТЗ 8.7, 9.3, 9.4 на API 5в (решение 038) и
сервисе Render (решение 036): где собирать и как отдавать интерфейс, что делать
с требованиями, которые сейчас не на чем выполнить, — предпросмотр «теми же
React-компонентами, что на сайте» (карточки сайта — компоненты Astro), разделы
без эндпоинтов, кнопка публикации до 5д, разметка текста 9.8, п. 1.

## Решение

Ответы Заказчика 21.11.2026 (правка ТЗ 3.31):

1. **Предпросмотр — отдельной задачей после 5г.** Она переводит карточки сайта
   на React; Astro рендерит их при сборке, JavaScript на публичных страницах
   остаётся 0 КБ. В 5г предпросмотра нет.
2. **Меню — только разделы с эндпоинтами:** Підприємство, Контакти,
   Керівництво, Послуги, Куди звертатися, Публічна інформація, Вакансії, Тексти
   сторінок, Кошик; владельцу в «Службове» — Словник стрічки и Змінити пароль.
   Пунктов «скоро» нет. «Користувачі» не показываются: учётная запись одна.
3. **Полоса публикации без кнопки до 5д:** число неопубликованных правок и время
   последней публикации из `GET /publish/status` (появляется в 5г; 5д добавит
   сведения о прогоне).
4. **Текст полей — обычный.** Разметка 9.8, п. 1 — отдельной задачей.
5. **Пакет `admin`** (Vite, React, TypeScript) в рабочем пространстве; собирается
   командой сборки Render, отдаётся сервером по `/admin/`. ТЗ 10.2 клало
   админку в `site`, но Astro и `sharp` на Render не ставятся (решение 037).
6. **Подпись раздела — «Тексти сторінок»** (как в API), ТЗ 9.3 исправлено.
7. **`/admin/help` — четыре рецепта** (телефон, вакансія, приховати картку,
   довго відкривається); «замінити фото» — с 5е, «опублікувати» — с 5д. Лист на
   печать — при передаче админки редактору.
8. **Один PR:** будильник на Pages, каркас, вход и выход, смена пароля, списки,
   формы, Кошик, полоса, помощь.

Решения разработчика:

- **Свой адрес сервиса в списке разрешённых `Origin`** изменяющих запросов —
  из `RENDER_EXTERNAL_URL`, который Render задаёт веб-сервису сам
  (https://render.com/docs/environment-variables, проверено 21.11.2026). CORS
  не расширяется: запросы админки не межсайтовые.
- **Сборка отдаётся из памяти, без `@fastify/static`** (отступление от
  рекомендации в вопросе 5; на выбор Заказчика не влияет):
  `server/src/gateway/admin-assets.ts` читает `admin/dist` при старте в
  таблицу. Файлов пять, путь ищется в таблице, а не на диске — выхода за
  каталог по `../` нет по построению; сжатая копия готовится один раз. Минус
  одна зависимость и её поведение с префиксом, которое документация не
  описывает.
- **Изменяющие запросы после таймаута не повторяются автоматически только при
  создании записи**: запрос мог дойти, повтор создал бы вторую. Форма
  остаётся заполненной, повтор — кнопкой (ТЗ 8.7, п. 4).
- **Маршрутизация — адреса `/admin/…`** через History API, без библиотеки
  маршрутизации. Сервер на любой `GET /admin/*`, кроме файлов сборки, отдаёт
  `index.html`; `/admin` переводит на `/admin/`.
- **Политика содержимого админки своя:** всё с `'self'`, без встроенных
  скриптов и стилей; у API остаётся `default-src 'none'`. Файлы с меткой
  содержимого в имени кэшируются на год, `index.html` — `no-cache`.
- **Поля формы описаны в админке** (`admin/src/domain/forms.ts`): подпись,
  подсказка «где появится на сайте», тип, предел длины. Типы данных — из схем
  `shared`; сами схемы Zod в браузер не едут: окончательную проверку делает
  сервер (422 по полям), админка лишь подсвечивает поле и ставит фокус.
- **Телефон вводится в любом виде** и приводится к `+380XXXXXXXXX` той же
  функцией `parseStoredPhone`, что и на сервере.
- **Служебные поля скрыты:** `order` — кнопками «вище/нижче», `slug` —
  только владельцу как «Адреса сторінки», с подтверждением после первой
  публикации; `photoPath` — с 5е; `status` вакансии пишет сервер.
- **Будильник на Pages** — страница сайта с одним скриптом (`script-src 'self'`)
  и `connect-src` на адрес сервиса; без JavaScript — прямая ссылка на админку.
  Адрес сервиса — `PUBLIC_API_BASE`, по умолчанию
  `https://uzn-desna-api.onrender.com` (не секрет, ТЗ 10.5).

## Отброшено

- **Перевод карточек на React в 5г** — PR вдвое и регресс всех страниц версии 1.
- **Дублирование вёрстки карточек в админке** — нарушает 9.3 и 10.2.
- **Пункты меню «скоро»** — редактор нажимает то, что не работает.
- **Неактивная кнопка «Опублікувати зміни» до 5д** — выглядит сломанной.
- **Админка внутри `site`** — на Render пришлось бы ставить Astro и `sharp`.
- **Собранные файлы админки в git** — артефакты сборки в репозитории
  расходятся с кодом.
- **Хэш-маршрутизация (`#/…`)** — ТЗ 9.4, п. 8 называет адрес `/admin/help`.
- **Библиотека форм и маршрутизации** — разделов девять, полей десятки; лишняя
  зависимость без выигрыша.

## Последствия

- В `render.yaml` сборка ставит и собирает `admin`; `buildFilter` включает
  `admin/**`.
- Задача «Предпросмотр карточек» и задача «Разметка текста» добавлены в очередь
  версии 2 после 5ж.
- 5д добавляет кнопку в готовую полосу и сведения о прогоне в `/publish/status`.
