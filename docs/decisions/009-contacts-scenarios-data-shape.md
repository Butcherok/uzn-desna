# 009: данные контактов и сценариев, область схемы `Enterprise`

Дата: 2026-11-16
Статус: принято

## Вопрос

Страницы «Куди звертатися» и «Контакти» живут на подтверждённых телефонах,
часах и почте. Нужно было решить три вещи: где эти значения хранятся, что
делать с полями `Enterprise`, которых ещё нет, и как телефон попадает в подвал,
не нарушая направление зависимостей ТЗ 10.2.

## Решение

**1. Три файла данных по конверту ТЗ 6.6, схемы в `shared`, проверка в `data:check`.**

- `data/contacts.json` — четыре `Contact`: приймальня, бухгалтерія, відділ кадрів,
  оперативний черговий. Отбор по `confirmed` и сортировка по `order` — слой
  `domain` (`site/src/domain/contacts.ts`), а не схема: файл вправе хранить
  неподтверждённую запись, страница — нет (ТЗ 4.6).
- `data/scenarios.json` — семь `Scenario`. `whatWeDo`, `phone`, `hours` не
  заполняются: с 16.11.2026 номер один на все ситуации (ТЗ 13.1 версии 3.4).
- `data/enterprise.json` — синглтон с единственным полем `email`. Ровно одна
  запись проверяется и схемой файла, и шагом `data:check`.

**2. Схема `Enterprise` описывает только подтверждённые поля.**

Остальные поля ТЗ 13.1 (`nameFull`, `nameShort`, `legalForm`, `ownerBody`,
`governedBy`, `kved`, `legalBasis`, `infoReference`, `structure`) приходят
задачей «Про підприємство» расширением этой схемы: их значения за заглушками
5–8, а выдумывать их нельзя. Это то же правило, что для `PublicDoc` в решении 007.

**3. Телефонов нет в `config/site.ts`.**

`phoneStored` и `hours` оттуда убраны: тот же номер в двух местах — прямой запрет
ТЗ 10.2 («значения, разбросанные по файлам»). Страница 404 берёт приймальню из
тех же данных. В `config` остались адрес, Facebook и ссылка на точку в картах:
полей для них в модели данных ТЗ 13.1 нет.

**4. Подвал получает телефоны параметром.**

Читает их оболочка `BaseLayout.astro` (слой страницы: `gateway` + `domain`),
`SiteFooter.astro` только выводит переданное. Так слой `components` остаётся без
ввода-вывода (ТЗ 10.2), а параметр не приходится протаскивать через каждую из
восьми страниц — подвал на всех одинаков.

## Отброшено

- **Хранить телефоны в `config/site.ts`.** Тогда их правка — правка кода, а по
  ТЗ 6.2 это редактируемые поля админки версии 2; формат данных при её появлении
  меняться не должен.
- **Читать данные прямо в `SiteFooter.astro`.** Запрещено ТЗ 10.2: слой
  `components` не делает ввода-вывода.
- **Завести все поля `Enterprise` сразу, с пустыми значениями.** Пустое
  обязательное поле — это заглушка, выданная за данные; схема перестала бы ловить
  неполную запись.
- **Класть текст блоков страниц в `StaticBlock`.** Перечень ключей `blockKey`
  закрыт (ТЗ 6.2), ключей этих двух страниц в нём нет; заводить их — правка ТЗ
  ради трёх строк связующего текста. Карточки и телефоны при этом в данных.

## Последствия

- Смена номера или часов — правка JSON, без правки кода; в версии 2 тот же файл
  пишет админка.
- Задача «Про підприємство» расширяет `enterpriseSchema` и переносит туда
  названия предприятия из `config/site.ts`.
- Появление второй неаварийной точки с `showInFooter` поменяет подвал: он берёт
  первую подтверждённую точку без `roundClock` и первую с ним.
