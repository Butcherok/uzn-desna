# 008: защита адреса электронной почты HTML-сущностями

Дата: 2026-11-16
Статус: принято

## Вопрос

ТЗ 5.4, п. 7 требует: адрес почты собирается из частей и выводится скриптом либо
хранится в закодированном виде; простого текстового `mailto:` в исходном коде
страницы нет. При этом ТЗ 11.7, п. 4 требует, чтобы публичные страницы полностью
работали при отключённом JavaScript, а ТЗ 11.2 держит бюджет JS публичных страниц
на нуле. Два требования ТЗ указывают на разные способы: «выводится скриптом» и
«работает без скрипта».

## Решение

Адрес и ссылка `mailto:` собираются числовыми HTML-сущностями: каждый знак
записывается как `&#NN;`. Браузер разбирает сущности при построении документа,
поэтому ссылка работает без JavaScript, а в исходном коде страницы нет ни
`mailto:`, ни собачки, ни букв адреса.

- Кодирование — чистая функция `encodeHtmlEntities` в `shared/src/format/email.ts`;
  готовая разметка ссылки — `mailtoLinkHtml` там же, с тестами.
- На странице разметка вставляется через `set:html`: обычная подстановка значения
  экранировала бы амперсанды сущностей и показала бы `&#107;` текстом.
- Сам адрес лежит в `data/enterprise.json` (поле `email`, ТЗ 13.1 версии 3.4),
  а не в коде страницы. В сборку этот файл попадает значениями, не файлом.

Проверено на собранной странице `site/dist/contacts/index.html`: поиск по строкам
`mailto:` и `kpuzn07` ничего не находит, на странице ноль тегов `<script>`.

## Отброшено

- **Сборка адреса скриптом из частей.** Прямо противоречит ТЗ 11.7, п. 4: при
  отключённом JavaScript житель не увидит адреса вовсе. И это первый скрипт на
  публичной странице при бюджете JS 0 КБ (ТЗ 11.2).
- **Картинка с адресом.** Нельзя скопировать, не читается экранным диктором,
  требует `alt` с тем же адресом открытым текстом (ТЗ 11.3).
- **Форма обратной связи вместо адреса.** Форм на сайте нет вовсе (ТЗ 1.2, 4.6).
- **Разделение адреса словами («kpuzn07 собака gmail точка com»).** Житель должен
  набирать адрес руками, ссылка не работает, выгода против сборщиков сомнительна.

## Последствия

- Защита держится на разборе сущностей, а не на скрытии: сборщик, который строит
  DOM, адрес увидит. Это принятый уровень — он же записан в ТЗ как достаточный.
- Правило относится и к подвалу (ТЗ 5.4, п. 7), но почты в подвале нет: ТЗ 3.1
  её в составе подвала не предусматривает.
- Строка чек-листа 12.2 «простого текстового `mailto:` в исходном коде нет»
  проверяется поиском по собранной странице, не глазами.
