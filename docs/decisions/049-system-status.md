# 049: раздел «Стан системи» — синхронизации и сервис через бэкенд

Дата: 2026-11-23
Статус: принято

## Вопрос

Прогон 12.3 (23.11.2026, `docs/findings.md`): раздел состояния синхронизаций и
`/system/info` описаны в ТЗ (8.6, 9.1, 9.3), но не построены. По ТЗ 8.6 админка
читала бы `sync-state.json` из своей сборки, но с 21.11.2026 она отдаётся с Render
(решение 040) и сборки сайта у неё нет. Кроме того, `sync-state.json` пишется
только при смене итога или счётчика сбоев, и его время у работающего источника
отстаёт на дни.

## Решение

Ответы Заказчика 23.11.2026 — «да, делаем по рекомендациям».

1. **Строим в версии 2**, до тега `v2.0.0`.
2. **Источник — сервер (вариант а).** `GET /system/sync` (только владелец):
   `data/sync/sync-state.json` из `sync-data` по `raw.githubusercontent.com` без
   токена и пять последних прогонов `Sync external` из API GitHub токеном
   публикации (`GITHUB_DISPATCH_TOKEN`, право Actions). Кэш 60 с, общий запрос;
   при сбое — прежняя копия с `fresh: false`, без неё — `null` («невідомо»).
   Токен в журнал процесса не пишется. `gateway/sync-status.ts`.
3. **`GET /system/info`** (только владелец): версия, время запуска, записи по
   разделам без «Кошика» (всего и опубликовано), последняя публикация,
   неопубликованные правки.
4. **Страница «Стан системи»** в «Службове»: по источнику — итог словами и
   причина, «Без збоїв з …» или «Останній збій: …», предупреждение со второго
   сбоя подряд; список прогонов со ссылками; предупреждение, если прогонов по
   расписанию не было 30 часов (как условие `kick-sync`, решение 048); блок
   «Сервіс». Число записей и «последний успех» из файла не выводятся: они
   устаревают.
5. ТЗ 8.6 и 9.3 исправлены (3.39); адрес журнала в ТЗ — `/log`, как в коде.

## Отброшено

- **(б) коммит `sync-state.json` каждый прогон** — три пустых коммита в сутки и
  расхождение со строкой 12.3 «коммит только при изменении».
- **Чтение файла из браузера** (`raw.githubusercontent.com` из админки) —
  второй источник в `connect-src`, а прогоны без токена всё равно не прочитать.
- **Отдельные разделы для синхронизаций и сервиса** — две страницы по одному
  экрану.

## Последствия

- При спящем Render раздел недоступен; сломанный источник по-прежнему видно в
  журнале Actions и в письме GitHub после третьего сбоя (ТЗ 7.5, п. 3).
- Без токена публикации раздел показывает источники, а прогоны — «недоступно».
