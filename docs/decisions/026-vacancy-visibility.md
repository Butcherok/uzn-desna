# 026: Видимость вакансий — переключатель и «Актуально до»

Дата: 2026-11-19
Статус: принято

## Вопрос

Как редактор управляет тем, какие вакансии видит посетитель, и как не оставить на сайте забытое объявление (озеленювач висит в открытых источниках с июля 2026).

## Решение

- Карточка заводится на должность и хранится. Видимость — переключатель «Показувати на сайті», поле `status` (`draft` / `published`, ТЗ 6.1, п. 5). До админки поле лежит прямо в `data/vacancies.json`; сборка выводит только `published`.
- Необязательное «Актуально до» (`validThrough`, `ГГГГ-ММ-ДД`): с этого дня по киевскому времени карточка не выходит, даже если переключатель включён.
- Срабатывает при сборке, поэтому `deploy` получил ежедневный запуск по расписанию (22:20 UTC — после полуночи по Киеву круглый год). Задержку запуска по расписанию GitHub не исключает: карточка может провисеть лишние часы.
- Дата публикации на странице не выводится (решение Заказчика 19.11.2026). `publishedAt` стал необязательным: админка проставит его при публикации для журнала.
- Телефон в карточке — всегда відділ кадрів (`viddil-kadriv`), а не номер из объявления-первоисточника: на сайте телефоны подразделений, а не людей (ТЗ 5.4, п. 6).
- Скрытая карточка не роняет сборку битой ссылкой на контакт: проверка — только у выводимых.

Заменяет в решении 025 пункт о дате публикации и отброшенную вакансию КМДА.

## Отброшено

- Справочник должностей отдельно от «відкриттів» вакансии (с датами, числом мест, историей) — так устроены кадровые системы, для одного редактора это лишний слой.
- Без «Актуально до» — забытая вакансия висит, пока её не выключат вручную.
- Скрытие по сроку в браузере посетителя — требует JavaScript на публичной странице (ТЗ 11.2).

## Последствия

- Схема `Vacancy`: поля `status`, `validThrough`; `publishedAt` необязательно (ТЗ 13.1, версия 3.20).
- `domain/vacancies.ts`: `isVisible`, `kyivDate`; страница передаёт дату сборки.
- `.github/workflows/deploy.yml`: расписание раз в сутки. Расписание в публичном репозитории GitHub может отключить после 60 дней без активности (ТЗ 7.1, п. 5) — та же оговорка, что у синхронизации.
