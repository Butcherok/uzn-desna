# Резервная копия: проверка ключа и восстановление

ТЗ 9.6; решение 045. Копию делает рабочий процесс `backup` (1-го числа ночью и
кнопкой «Створити резервну копію» в админке, раздел «Резервні копії»). Каждый
прогон сам проверяет копию: расшифровывает её одноразовым ключом, поднимает в
чистой MongoDB и сверяет число документов — таблица в отчёте прогона.

Этот документ — для владельца: всё, что требует закрытого ключа, делается
только на его компьютере. Закрытый ключ, пароли и строки подключения — не в
чат, не в репозиторий, не в почту.

## Что понадобится (один раз)

PowerShell, команды по одной:

```
winget install --id FiloSottile.age
```

```
winget install --id MongoDB.DatabaseTools -e
```

После установки закрыть окно PowerShell и открыть новое. Проверка:

```
age --version
```

```
mongorestore --version
```

Должны напечататься номера версий. `mongorestore` не найден, а winget пишет
«Найден существующий установленный пакет» — папка утилит не попала в `PATH`
(24.11.2026, у владельца). Найти её и добавить в `PATH` пользователя:

```
$dir = (Get-ChildItem "C:\Program Files\MongoDB" -Recurse -Filter mongorestore.exe | Select-Object -First 1).DirectoryName
```

```
[Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path","User") + ";" + $dir, "User")
```

Закрыть PowerShell, открыть новое окно, повторить проверку. Для шагов 1–2
`mongorestore` не нужен — только для шага 3.

## 1. Скачать копию

1. GitHub → `Butcherok/uzn-desna` → **Actions** → слева **Backup**
   (или в админке «Резервні копії» → «Усі копії, зокрема щомісячні»).
2. Открыть зелёный прогон с нужной датой → внизу блок **Artifacts** → файл
   `uzn-backup-ГГГГ-ММ-ДД-run….archive.gz.age` → скачается `.zip`.
3. Распаковать `.zip` в папку, например `D:\backup`. Внутри — один файл `.age`.
4. На той же странице прогона, вверху, — таблица «Резервна копія: перевірена» с
   числом документов по коллекциям. Сохранить её (снимок экрана): она нужна
   для сверки после восстановления.

Хранить у себя три последние копии: GitHub удаляет их через 90 дней.

## 2. Проверить свой ключ (один раз, до передачи админки редактору)

Закрытый ключ из менеджера паролей сохранить во временный файл
`D:\backup\key.txt` (весь текст, вместе со строкой `AGE-SECRET-KEY-…`).

```
cd D:\backup
```

```
age -d -i key.txt -o uzn.archive uzn-backup-ГГГГ-ММ-ДД-runНОМЕР.archive.gz.age
```

Имя файла — полностью, как в папке (`Get-ChildItem *.age`). Маска вместо имени
при двух копиях в папке даёт `too many INPUT arguments`.

Должно: команда завершилась без сообщений, появился файл `uzn.archive`
размером в десятки килобайт (24.11.2026 — 14 379 байт: архив сжат). Размер:
`(Get-Item uzn.archive).Length`. Сообщение `no identity matched any of the
recipients` — ключ не тот: копия зашифрована другим открытым ключом.

Записать в журнал решений ТЗ (13.3, «Прогоны восстановления»): дата, «ключ
владельца расшифровал копию run…». После проверки:

```
Remove-Item key.txt, uzn.archive
```

## 3. Восстановить БД (авария: данные потеряны или испорчены)

**Перед этим** — свежая копия текущего состояния кнопкой в админке, если
админка ещё открывается: восстановление заменяет данные целиком.

1. Расшифровать, как в шаге 2 (`key.txt` → `uzn.archive`).
2. Строка подключения пользователя `uzn-api` (право записи в `uzn`) — в
   Render → сервис `uzn-desna-api` → **Environment** → `MONGODB_URI`. Скопировать,
   в чат и в файлы не вставлять.
3. Восстановить (значение строки — вместо `СТРОКА`, в кавычках):

   ```
   mongorestore --uri "СТРОКА" --nsInclude "uzn.*" --drop --gzip --archive=uzn.archive
   ```

   Должно: в конце `… document(s) restored successfully. 0 document(s) failed
to restore.` `--drop` заменяет коллекции копией; сессии в копию не входят —
   все входят в админку заново.

4. Render → сервис → **Manual Deploy → Restart service**: индексы и первый
   владелец проверяются при запуске.
5. Войти в админку. Сверить число записей с таблицей прогона из шага 1:
   «Журнал дій» — записи до даты копии; разделы — карточки на месте.
6. «Опублікувати зміни» → дождаться «Усі зміни опубліковано» → сайт собран
   из восстановленных данных.
7. Удалить `key.txt` и `uzn.archive`. Записать восстановление в журнал решений
   ТЗ (13.3): журнал действий сам его не видит — его заменила копия.

## Если прогон `backup` красный

- `BACKUP_NOT_CONFIGURED` — нет секрета `BACKUP_MONGODB_URI`: GitHub →
  **Settings → Secrets and variables → Actions**.
- `Authentication failed` в шаге **Dump database** — пароль пользователя
  `uzn-backup` в секрете не совпадает с Atlas: Atlas → **Database Access** →
  `uzn-backup` → **Edit** → новый пароль → обновить секрет.
- `BACKUP_MISMATCH` — копия не совпала с исходной БД: повторить кнопкой; если
  повторяется — копию не использовать, показать отчёт агенту.
